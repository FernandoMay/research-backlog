# P1 Defect Report 004 — SGN, steganography benchmark

**Date:** 2026-09-30
**Package:** `FernandoMay/sgn-ieee-package`
**Corpus:** P1 research-hardening sweep. **Separate from the E1 dataset**, frozen at v1.0.
**Status:** Frozen. No number corrected, no file modified, no claim rewritten, no repair started.
**Method:** the `bit accuracy = 0.50` claim was opened from the producer side and traced through the whole path, per the standing rule that the question is whether a failing value indicates a failing predictor or a badly defined metric.

---

## 1. The path, traced end to end

### 1.1 `bit_accuracy` is correctly defined

`sgn_simulator.py:547`:

```python
def bit_accuracy(original_bits, extracted_bits, n):
    n = min(n, len(original_bits), len(extracted_bits))
    if n == 0:
        return 0.0
    return np.mean(original_bits[:n] == extracted_bits[:n])
```

Fraction of correctly recovered bits over the first `n`. This is the standard definition and it is implemented correctly. **The metric is not the defect.**

### 1.2 The payload is uniform random

`generate_secret_message` returns `rng.integers(0, 2, n_bits)`. There is no structure a method could exploit or be penalised for. A correct decoder must therefore score 1.0 on every method, or the embedder destroyed the payload.

### 1.3 The LSB decoder is broken by an indexing error

`LSBSteganography.encode` writes bit `i` into the least significant bit of pixel `i` — one bit per pixel, `bpc = 1`.

`LSBSteganography.decode`, line 172:

```python
mask = (1 << self.bpc) - 1
bits = np.unpackbits(np.array([flat[i] & mask for i in range(len(flat))], dtype=np.uint8))
```

Each masked pixel is a value in `{0, 1}`. `np.unpackbits` treats every element as **eight** bits and expands it, so each pixel yields `0000000b` — seven structural zeros followed by the real bit. The decoder returns **8 bits per pixel** where the encoder embedded **1**.

### 1.4 Verified empirically

Standalone replication of the repo's own encode and decode, `bpc = 1`, 192 pixels, 5000 random secret bits:

| quantity | value |
|---|---|
| extracted stream length | 1536 |
| pixels | 192 |
| ratio | **8.0×** |
| structural zeros in the first 64 decoded bits | 60 |
| `bit_accuracy` **as written** | **0.4961** |
| `bit_accuracy` with a 1-bit-per-pixel index | **1.0000** |

And through the repository's own `evaluate_method`, single `natural_like` cover, 5000-bit payload:

| method | PSNR | SSIM | bpp | bit accuracy | embedded bits |
|---|---|---|---|---|---|
| LSB | 61.02 | 1.000 | 0.102 | **0.5078** | 5000 |
| DCT | 50.02 | 1.000 | 0.004 | **1.0000** | 200 |
| GAN_Enc | 40.24 | 0.996 | 0.083 | **0.5046** | 4096 |
| Adaptive_JND | 61.09 | 1.000 | 0.102 | **0.4910** | 5000 |

The README table reports 0.50 / 1.00 / 0.50 / 0.51 for the same four methods. The pattern reproduces.

**Answer to the question the audit was opened to settle: 0.50 is a failing decoder, not a badly defined metric, and not a failing embedder.** LSB recovers its payload perfectly. The published figure is an artifact of `np.unpackbits` diluting every pixel to eight bits, and it is indistinguishable from a coin flip precisely because a uniform-random payload compared against a stream that is seven-eighths structural zeros scores at chance.

The paper never claims LSB recovers poorly. The defect is confined to the README table, plus one unbacked qualitative adjective in the paper's own text.

## 3. Second defect — the comparison is confounded by capacity

DCT scores 1.0000 and LSB scores 0.5078, and the README presents them in one column. But DCT embeds **200 bits** and LSB embeds **5000** — a factor of 25. DCT's decoder is correct and LSB's is not, so the column compares a working decoder against a broken one while also varying capacity by 25×.

`paper/en/main.tex:190` is more careful: "DCT achieves perfect bit accuracy but at very low bpp." That framing is correct. The README table drops the qualifier and presents the two values as comparable.

## 4. Scope boundary — stated rather than assumed

GAN_Enc (0.5046) and Adaptive_JND (0.4910) show the same chance-level symptom, but **neither uses `np.unpackbits`**; each implements its own `decode`. The mechanism proven in §1.3 is therefore established for LSB only. For the other two the cause is **not established**, and no cause is asserted here. The search performed was: class map over all 17 top-level definitions, and a scan of the `decode` body of each of the four steganography classes for `unpackbits`, which appears in `LSBSteganography` alone.

## 5. Reproduction status

- Metric evaluation reproduces exactly through `evaluate_method`, bypassing `main()`.
- **`main()` does not complete in this environment.** Three successive missing dependencies (`matplotlib`, `scipy`, `sklearn`) were installed; the final `scikit-learn` resolved to a broken distribution raising `ModuleNotFoundError: No module named 'sklearn.callback'`. This is an environment failure, **not** evidence about the package, and it is recorded as *not executed* rather than as a result.
- The paper's PSNR values (61.1 / 50.4 / 40.2 / 61.0) differ slightly from the single-image values above (61.02 / 50.02 / 40.24 / 61.09) because the published figures aggregate over a dataset. That is expected and is not a discrepancy.

## 6. Classification

Reproduces: **partially** — the metric path yes, the full pipeline not executable here.
Published numbers real and correctly produced: **yes**.
Mechanism connected to the result: **no**, for LSB.

| defect | location |
|---|---|
| Decoder indexing error producing a chance-level published metric | `LSBSteganography.decode`, `sgn_simulator.py:176` |
| Artifact with no numeric content, so no published figure is traceable to a committed value | `figures/metrics.json` |
| Unbacked qualitative claim about a value the artifact contradicts | `paper/en/main.tex:190` |
| Comparison presented without its capacity qualifier | `README.md:20-26` |

This is a **fifth profile**: a defect confined to the extraction path, invisible in the artifact because the artifact contains no numbers, and absent from the paper entirely — the README is the only place the wrong value appears, which is the reverse of the QCE pattern where the paper carried the stronger label.
